# 翻译候选查询与引用重试边界

此补丁接续历史范围与公平调度，新增迁移 `0071_quote_translation_attempts.sql`。先迁移，再升级翻译 coordinator；不要与其他来源策略迁移混作同一次未经审查的发布。它不设置 `GEOHOT_TRANSLATE_FROM`，不改变正文、引用、模型服务预算或并发上限。

正文与引用的候选 SELECT 在短只读事务中执行，服务端 `statement_timeout=2000ms`、`lock_timeout=250ms`；事务结束后才调用模型。超时使本轮失败并保留待处理状态，不清空尝试记录、不改写未知费用，也不把候选查询失败说成“没有待翻内容”。这是耗时保护，不保证查询能在两秒内完成：正文的全候选排名与引用的去重排序仍需要线上计划和受控运行验证。源码之外的数据库连接超时、网络响应时间和单行超大文本也不能由这一个 statement timeout 完全覆盖。

引用在数据库中先按 tweet ID 选范围内最新父文章，再按原文 UTF-8 SHA256 对照已有译文和持久失败记录。每次最多返回 30 个候选；先取得此有界结果，再查这些候选自己的完整中文译文，避免把全部候选全文带回 Node。尚未检查的候选优先，其次最近检查时间最早的候选，最后以父文章发现时间和 tweet ID 排序。候选结果有界不表示上游数据库去重工作只扫描 30 行；SQL 超时负责限制这部分工作。

`quote_translation_attempts` 按 `(tweet_id,text_hash)` 保存次数、结果、固定原因码与最近检查时间：

- 模型抛出普通错误或返回结构有效但无中文的答复，计一次失败；同一原文最多三次，跨进程重启保留。计数是处理失败次数，不能拿它作为收费次数；已收到的坏答复可从回执免费复用，也会消耗这个有界失败机会。
- Busy/Unknown 只记录 deferred 和检查时间，不增加失败次数，不解除或清理原有回执。它们往后轮转，让其他有限积压有机会推进。
- 中文、非文字或过短的引用按既有规则记录 skipped，不能记作成功译文。该原文哈希将不再重复占候选页。
- 成功写入的引用译文与 translated 结果在同一事务保存。原文变更只启用新的哈希记录，旧失败记录保留。

引用仍使用原来的共享翻译槽位，正常 coordinator 每轮至多一次引用模型机会；未增加独立 worker、cron 或账号预算。只有一个 coordinator owner 的运行约束仍然成立，本补丁没有加入多 owner 分布式候选认领。固定页容量和公平顺序可推进有限积压，不能保证任意无限新流量下每条记录的严格服务期限。

新表只保存标识、哈希和固定原因，不保存模型错误全文。它没有指向父文章的级联删除，因为一个引用可以由多个父文章共享；保留及人工审核策略需单独制定，不得通过删除失败/未知证据制造“已完成”。

正文 60,000 个叶子块 HTML 字符预算、超限尾巴、首块本身超限而 skipped、既有正文三次尝试上限仍是历史完整翻译的独立边界。扩大历史窗口前还需核验实际 discovery/revision 日期范围、线上查询计划、读者接口和资源表现，并分别报告这些未完成项。
