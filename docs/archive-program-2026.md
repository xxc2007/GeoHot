## 推进顺序与完成门槛

1. 核对本地、GitHub 发布树和服务器基线，保护已有宣传片和工作区修改。
2. 修复采集/出版控制缺陷，验证后安装单实例有资源上限的服务器持续任务。生产模型继续走预算、回执及原有双次评分，禁止直接写精选或用人工假分数制造通过。
3. 同时补期刊档案和非论文材料；历史材料保留出版时间、发现时间与原文，按 `archive` 投递进入它所属的历史报刊。不能把旧资料重锚到今天。
4. 每轮采集后更新月度账本。未定材料继续分析，不提前把那天排成最终版。失败、未知日期和不支持历史的信源单独保留，不以空结果宣称完成。
5. settled 日期按旧到新补日报，再补完整周/月。未结束周/月保持尚未到出刊时间的状态。最后等待本轮所有材料完成判定与投影后，全区间一次 `--refresh`，保持既有期号。
6. 多个独立检查 agent 验证全部可枚举页面、接口、刊物引用与代码边界。对无限变化的外部原文做可追踪抽检，报告实际覆盖和外部失败，不能承诺不存在任何错误。
7. 发布最终源码树并核验 GitHub、服务器和本地文件一致；带 BASE_PATH 构建、验证四服务、邻站、浏览器互动和机器出口。
8. 仅清理本轮登记的临时残留、测试数据库和可重建缓存；数据库、源文件、既有交付和迁移备份不删除。运行 `portable-backup.sh` 将源码、数据库、持久文件、私有配置、运行服务与校验清单存到服务器，完成隔离恢复演练后再结束目标。

未达上述门槛时保持任务进行中，尤其不能把“历史材料已入库”报告为“历史报刊已全部出刊”，或把“归档能列出”报告为“已恢复成功”。
