## 付费回执关键补丁的独立核对

`requestFor()` 同时构造真实 HTTP 请求与候选回执 identity，包含每个模型的 model、promptVersion、system/user hash、temperature、maxTokens（含 reasoning headroom）、json 与 extra。候选从当前 purpose 对应的真实配置池取得；显式池外模型或单模型切换不会偷偷恢复池外回答。

`paidRequest()` 在查询回执前按所有候选服务名的固定顺序取得事务预算锁，再按 id 取得回执行锁。logical key 包含 service：会竞争同一候选 key 的两个池选择，至少共享该服务锁，因此当前配置内的并发切换不能同时为同一步骤购买两次。received/completed 先恢复，无已收到回答时 pending/unknown 阻止另一个池成员购买。失败且确认未接收的步骤可以依法重试，仍使用相应服务预算。原模型健康统计仅使用 `origin='live'` 的已明确状态，不把正在请求的 pending 当作失败。

独立 `geohot_a18_test` 数据库中，`tests/receipt-pool-recovery.test.ts` 九项全部通过：预筛已成功但评分失败后的池切换恢复、unknown 拦截、stale pending 转 unknown、缺失旧候选凭据仍可复用其回执、并发 in-flight 保护、两次独立评分的 attemptTag 分离、候选参数变化拒绝错配、单模型切换边界、输入/提示词/JSON/重跑标签变化拒绝错配。所有请求仅发送至 localhost stub，没有使用生产模型或生产库。生产现有回执内容与真实服务状态由运维检查另行验证。

## 第二阶段：预算候选原子选路与拒绝者归属复核

确认的行为如下：

- 精确缓存恢复先于预算检查；当前配置池任意 pending/unknown 在没有已收到回答时阻止跨服务重送。
- 所有候选服务的预算锁先在一个事务内按固定顺序取得，再原子选用可支出的健康候选；同服务别名预算被挡后跳过重复检查。
- 只有外发前的本地 `BudgetExceededError` 会选择替补。选中的 request、receipt、HTTP call 闭包与真实模型一致；HTTP 失败、内容过滤拒绝、已发请求 timeout 不在本次调用中自动尝试下一家。
- 替补限于相同 capability 的当前配置池、健康且凭据/格式可用的成员；含 image_url 的请求额外要求 vision。单模型或显式池外模型维持原边界。
- 评分继续保留 score-1/score-2 独立标签；已答预筛与第一评分在预算满时仍从精确回执恢复，缺失的第二评分才建立新 attempt。

独立审阅发现一项 P2 审计元数据缺陷并推动最小修复：default 预算满而首次评分由 CN 替补，CN 返回内容过滤拒绝时，原先 `answeredModels` 为空，会将 scoreModel 写成 default。该问题没有将拒绝改为成功，也不造成跨服务重送，但会错误归属拒绝者。a16 已给 `ProviderRejectedError` 增加向后兼容的可选 modelKey，由真实 dispatch 的 HTTP/明确连接拒绝填充；runScores 在 refusal 中合并成功响应模型与真实拒绝模型。首评分、后评分被 CN 拒绝的三成员测试均保持 refused，第三个 localhost stub 为零请求。

## 2026-10-11 追加：事实归组的真实性边界

仅静态复核 `tests/geography-grouping.test.ts` 的既有 gap case 与当前 events/relate、events/group、publication/publish 和 reports/compose 路径，未执行新模型请求或修改判断规则。SAME_OCCURRENCE 按提示词表示同一次现实发生或官方发布，要求比较时间窗、同粒度地点、现象、量级与发布动作；提示词明确字面包含不等于同一地点。

事实归并当前没有独立置信度门：sameOccurrence 只按 relation 筛选，confidence 用于排序；高召回相似度可直接入 fact，低相似度的第二模型确认也只返回 relation。跨 story consolidation 的置信度门不能据此宣称覆盖 fact join。fact 归并会写入 publication.fact_id，报刊候选按 fact 只保留一条，日报再按 fact 做前七日去重；错误归并因而可能影响公开来源聚合并抑制独立发生入刊。这是有实际影响路径的既有安全边界，但 0.51 回归夹具描述同一地震的修订测定，未证明该次归并错误，更未证明生产已有错并。

“芦山县与天全县”夹具的桥接材料写明两县交界地震，原两条材料没有不同精确发生时间、震中坐标或权威事件编号。一次边界地震可能按两县分别描述，因此测试末尾“two different epicentres”的文字超出夹具证据；该测试仅证明程序信赖模型关系且没有独立地理校验，不能作为已证地名错并结论。

当前保留人定规则，不擅自把 story 的 0.8 迁为 fact 阈值，不以未经验证的地名匹配替代模型判断。后续宜用人工标注的同/不同发生样本校准事实归并，并用可信事件编号、明确不同时间与震中等证据验证冲突场景；生产影响需逐条核对现有决策和原始材料。全套代码测试不能形式化保证全部科学事实判断正确。
