# 移动阅读与性能独立复核（2026-10-10）

这是第 14 个辅助检查智能体的实际浏览器检查记录。检查对象是当前本地代码构建的生产 SSR，以及部署前的线上版本。该记录不等于最终部署验收，也不等于所有内容、所有设备已通过。

## 方法与范围

读取了根 AGENTS.md、README.md 和运营手册。使用仓库已有 `scripts/mobile-audit.ts`、`scripts/mobile-flow.ts` 驱动独立临时 headless Chrome，视口 320×844 和 390×844，触摸模拟、deviceScaleFactor=3。没有改业务代码、生产服务、README 或宣传材料。

本地使用 `npm run build -w @aihot/web` 生成生产构建，SSR 在临时 3414 端口运行，通过临时 3415 HTTP 只读桥读取线上公开 API；未读取生产数据库或凭据，也没有触发模型调用。与纯开发模式相比，这避免把 HTTPS upstream 与开发代理不兼容误判成站点功能故障。桥的局限是线上返回的 `/geohot/` 图片地址仍包含生产子路径，根路径本地构建会出现 icon 与部分头像的 404；这些不能作为生产图片故障证据。

第一轮宽度审查分别访问首页、全部、搜索入口、日报、周报、月报、日报归档、更多、主题，共 9 个有效页面，两个宽度共 18 个有效页面状态。另两条尝试路径 `/weekly/archive`、`/monthly/archive` 返回明确 404；它们不是本站定义的归档入口，不记为功能缺陷。周月报往期使用报告页内 `#report-history`，不足多期时不提供虚假的往期链接。

本地原始记录在本轮私有工作目录 `.round11/a14-mobile/report.json`、`a14-flow320/steps.json`、`a14-extra320b/steps.json`，修复回归记录 `a14-fixed320/steps.json` 和 `a14-fixed390/steps.json`。这些路径是当前工作目录外的本轮检查产物；本报告保存关键结果，最终清理时可移除临时浏览器目录。

## 结果与实际修复

- 18 个有效页面状态的页面级横向溢出均为 0px；页面滚到底时最后一块正文被固定底栏遮挡均为 0px。滚动经过底栏下面的中间卡片属于固定导航正常行为，不能等同于“最后内容永远不可见”。
- 首页和全部页面的分类栏宽于屏幕，但它是有意设计的内部横向滚动容器。修复后的“地理信息系统”选中项在 320px 时范围为 151–257px，在 390px 时为 221–327px，完全处于可见宽度内，`aria-current=page`。
- 320px 日报日期条初始“更早”按钮部分位于屏幕外。实际将日期容器滚到末尾，scrollLeft 从 0 增至 22px，按钮右端成为 303.75px，能够触达；因此不报页面裁剪缺陷。
- 首页点击“前沿地理”后 URL 正确为 `/?category=frontier`，页面滚动从 1200px 回到 0，列表内容变化。打开真实详情页，标题和 h1 一致；返回后恢复之前 600px 的滚动位置。
- 更多入口导航到 `/more`；搜索表单用 `q=气候` 提交后 URL 正确，标题为搜索“气候”，输入值保留，返回真实搜索结果（当时 310 条，计数会变）。
- 发现并向根智能体报告了一个实际焦点缺陷：从首页点击搜索导航到 `/all?search=1` 后，输入框已存在，但焦点在 `main`。源码原因是 `root.tsx` 的 pathname 效果覆盖 `Filters.tsx` 中 SearchField 的 autoFocus。冷启动直接打开该 URL 时输入框可以获焦，说明缺陷集中在客户端导航。
- 根智能体修复后重新构建并重启本地 SSR。320px 和 390px 两次真实点击首页搜索回归都得到 `focused=input`，URL 与输入框正常。这是修复后的本地证据；上线后仍应在 `/geohot/` 子路径回归。
- 日报标题在 320px 真实截图中可完整阅读，底部导航为 55px 高。搜索入口的新 44px 点击区域已体现在本地检查。更多页外观切换按钮约 39×44px、RSS 约 34×44px，报告原文链接部分约 39×44px，仍有偏窄点击区域；这是次要体验建议，没有据此修改代码。

## 线上加载测量

线上测量对象为部署前的 `https://xxc2007.me/geohot/`。每个数字来自一次 Navigation Timing / Paint Timing 采样，非统计分位值。后续页面沿用同一浏览器缓存，因此不能与首个冷启动页面公平比较。

| 页面 | 首字节 TTFB | 首次内容绘制 FCP | load 事件 | 缓存状态说明 |
| --- | ---: | ---: | ---: | --- |
| 首页 | 1598ms | 2240ms | 2298ms | 新浏览器配置，冷启动 |
| 全部 | 487ms | 708ms | 720ms | 同会话缓存共享资源 |
| 日报 | 322ms | 720ms | 681ms | 同会话，首次报告资源 |
| 周报 | 367ms | 628ms | 623ms | 同会话缓存 |
| 月报 | 218ms | 292ms | 282ms | 当时呈现未出刊空态，不能与完整报告比较 |

五个线上页面没有捕获到 JS 异常、失败网络请求或 HTTP 4xx/5xx。FCP 与 load 来自不同性能事件，采样不要求 FCP 一定早于 load。

首页资源记录中：入口 `entry.client-yIBOhxhd.js` 解码为 346,968 字节，传输 112,085 字节；全部 JS 解码约 465,141 字节；浏览器资源传输总计 202,484 字节（另有文档传输 34,519 字节）。不同指标不能相加后当“JS体积”，也不能把缓存资源的零 transferSize 当作资源不存在。

另做一次明确配置的模拟慢手机检查：禁用缓存，100ms 网络延迟，下载 200,000B/s（约 1.6Mbps），上传 75,000B/s，CPU slowdown rate=4，390×844 视口。首页 TTFB 1346ms、FCP 4544ms、DOMContentLoaded 4732ms、load 4979ms，没有捕获 JS / 网络错误。这说明慢设备首次打开仍有改善空间；不证明真实手机的耗时，也不构成性能评分。建议以此作为优化前基线，评估 SSR 首字节与首屏 JS、动画依赖加载，再用相同条件多次重测收益。

原始线上记录为本轮私有目录 `a14-online-perf/report.json` 与 `a14-throttled/report.json`。本次没有测量 LCP、INP、CLS 的可靠全生命周期值，没有 Lighthouse 评分，也没有 Safari、真 Android/iPhone、系统键盘、屏幕阅读器或连续弱网断线检查。
