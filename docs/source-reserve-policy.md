# 正式与备用信源

站长指定的运行池为 1000 个入口：666 个正式采集、334 个备用。记录和数量以后台数据库为准，`industry/source-reserves.json` 是此次经验证的备用入池清单，不是永远有效的健康证明。

无效入口移出运行池。仍被文章、报刊等引用的信源保留为历史来源档案，后台运行池不再计入；没有任何外键引用的旧记录可删除，完整原始记录仍保存在私有归档表。不会删除历史文章、精选或报刊引用。旧 seed 不会自动恢复已归档的 ID。

每五分钟执行一次有界维护，串行复核最多四个备用源，每个备用源每日复核。仅公开 RSS 或 JSON 入口，无付费采集、无模型调用。备用源须有标题、链接和最近 400 天内的有效日期；论文目录可低频更新，验证不表示论文全文可免费获取。Crossref 是出版机构提交的期刊元数据，按真实期刊分别登记，不将其误写成出版商直供全文。未来印刷日期优先使用已发生的在线发表日期，否则跳过。

自动替换条件：正式源连续失败至少五次、至少 24 小时无成功、最近六小时内确实尝试过采集。预算、限流与 429 不触发替换。备用入口需在最近七天验证合格，并在切换前再次通过网站实际采集器的即时验证。优先相同分类、一手属性及质量优先级；不匹配明确分类时不强行替换。

每轮最多替换两个，每滚动 24 小时最多十二个；若失败源达到正式池的十分之一（小站至少十个），停止自动轮换，保留故障供排查。切换在同一个数据库事务与注册表锁内完成，并再次核对数量、失败证据和资格，始终一停一启，记录 `source.auto-replace` 审计。失败旧源进入隔离区，不立即反复回切；每日复核恢复后才可重新候选。因此运行池仍为 1000，备用中「已验证可用」与「隔离待复核」分别显示。

启用数量上限与运行池上限由数据库约束、注册表锁保护。自动功能默认关闭，迁移本身不启用，不改旧站数量；只有显式运行 `scripts/provision-source-reserves.ts --manifest=industry/source-reserves.json --apply` 且原有正式池恰好 666 个、清单恰好 334 个且验证未过期时才启用。去掉 `--apply` 为只读预览。生产执行前保存注册表备份，完成后读回运行池、备用与审计。

后台导航的「设置」固定放在业务目录最后，审计记录位于设置之前。
