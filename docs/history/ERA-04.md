## 二、读者面：不再让第一个读者替全站等冷算

**改了什么**

- 页面缓存由定时器预热：`geohot-warm-hot`/`geohot-warm-pages` 在过期前后各刷一次；首页与「全部」另有 60 秒预热带。
- 时间线与收录池留**落盘底稿**：`/api/site/pool` 每页成功答案落一份到 `.data/pool-snapshot/`（`pool:` 与 `tl:` 两种 key），进程刚起来时直出上一份并后台刷新。
- 取不到新数据时交上一份好页面：每个 GET 的成功正文留最多 10 分钟，超时/读不到/上游 5xx 交出旧页（带 `x-aihot-stale`），404、重定向、4xx 不参与兜底。
- 移动端「全部」不再等收录池：等待文案换成同形状骨架，数据到了原地替换；手机进站即可见「全部」，月历不再依赖 URL。
- 主题页与后台列表改触底续读（`Pager` 组件删除）。
- 缓存与索引收口：历史日期给一天缓存、组合筛选页不进索引；`/all` 补一条不带 `eligible` 的部分索引；主题计数缓存与页面缓存同频（1 分钟 → 5 分钟）；时间线快照 5 秒 → 30 秒 → 10 分钟。
- 冷启动取数预算给到 12 秒，并把「慢」与「故障」分开；首屏预算后来压到 3.5 秒（R22 批次）。

**为什么**

- 提交正文记录的事故：2026-11-06 01:4x 夜档开起来后，SSR 取时间线偶尔超过 15 秒，`AbortSignal` 一断就整页 503。
- 主库只有一块慢盘（891 MB / 2 vCPU / 单盘 ~250 IOPS）。`docs/reader-first-throughput.md` 的实测结论：一个分析槽把磁盘占满，首页冷请求就从 35 ms 推到 2.4–5 s；所以读者面的速度不是「给读者更多名额」，而是**让读者根本不落到数据库上**。
- 爬虫对组合筛选页的笛卡尔积请求，不该由读者内存来付。

**影响**

- 对读者：重启、慢盘、上游抖动都不再表现为空白页或 503；最坏情况是看到几分钟前的页面，且响应头明说这是旧页。
- 对运维：重启窗口不再需要人肉「先自己走一遍首页」；预热带与 stale 兜底把「部署后第一个读者买单」这一类事故关掉。
- 代价是缓存层数变多（nginx stale、进程内快照、落盘底稿、cdn 边缘），排查「为什么我看到旧内容」要先看 `x-aihot-cache`/`x-aihot-stale`。

## 四、模型与计费：池子要能死得干净，账要能算得清

**改了什么**

- 冷却表的持久化在本时代开始前几小时刚落库（`45518d2546f0`，2026-11-05 01:27）；本时代接着把它从「有时间」升级成「有分类、有证据」：quota_day / rate_minute / auth / config 四类，解析 `Retry-After`（秒或 HTTP-date）与 body 里的 reset 时间；没有证据就退回保守默认并标 `resetAssumed`。只有 400/401/402/403/404/429 记 `unbilled` 并同调用内换成员；通用 5xx/超时记 `unknown` 且不重放；网关侧已死的成员立刻冷却，不再每轮白烧一次。
- 池子换血：hy3 三条别名退休，换 hy4 flash；agnes 提到 `reasoning_effort=max`（实测隐藏推理 low 183 < high 196 < max 203 token）；把 magpie 里实测能答话的九个门登记进注册表；用 1-token 探针实测出 404 清单，摘掉 11 个死别名（五台机器分别摘 100/98/97/97/97 个成员位）。
- 计费口径重写：`billing_kind` 分为 actual / equivalent-public-api / subscription / free / no-price / unverified；A/B/C 三份映射合并为 47 条种子，订阅/免费/无公开价的费率存 NULL，**绝不按 0 计价**。
- 价卡版本化（0124）：调用按 `started_at` 选当时有效的 `pricing_rate_versions` 行，没有有效版本就是 unpriced，绝不拿最新价倒算历史；刷新走异步工具 + systemd timer，HTTP 200 单独不能算「价已核验」，失败保留 last-good 并标 stale。
- 用量页拆分：reasoning token 由 0125 迁移派生并回填，只读展示、不计入成本；缺失标签不再让整页失败；快照 store 与缓存版本号上调，避免旧形状的 24 小时快照被当成新价读。

**为什么**

- 冷却持久化的动机写在上一时代末那条提交里：worker 当天被停起六十多次，冷却只在进程内存里，每次重启都把已确定死掉的成员放回轮转，白烧一次调用。本时代要解决的是它之后的问题——成员为什么会死、死了多久、什么时候该回来。
- 11-16 的事实：一小时 60 次失败的模型调用里，一半是池子里的死成员——分派过去先撞一次 404 才轮到下一个模型。
- 计费侧的动因写在 0124 的注释里：刊例价不是账单，`actual` 成本只能来自回执 `cost_basis='actual'`；无价条目存 NULL 是为了让「不知道」显式存在，而不是伪装成 0。

**影响**

- 对运维：冷却在重启后仍在（上一时代末落库），本时代补上的是「分类 + 证据 + 恢复条件」；换模型有实测清单，不靠 `/v1/models` 对表（magpie 吃别名，对表会造出假死）。
- 对账：用量页第一次能区分「真实账单」「等值公有云 API 价」「订阅内」「免费」「无价」「未核实」，并给每条价卡标注抓取时间与生效版本。
- 对外：死别名与 404 成员下线后，同样的预算能落到真正能答话的成员上；`docs/admin-official-pricing.md` 在 11-18 与 11-20 多次同步了计费口径。

## 六、安全：把「仓库里不该有的东西」清出去

**改了什么**

- 生产主机地址从仓库移除：隧道/边缘/执行器安装脚本改读 `GEOHOT_PRIMARY_HOST`/`GEOHOT_HANGZHOU_HOST`，缺失就显式报错而不是连一个写死的地址；备份/拉取脚本把目标落到机器上的 640 本地文件；systemd 模板用 `__GEOHOT_PRIMARY_HOST__` 占位符由安装脚本替换。
- 后台面板的机器地址改由环境变量下发，仓库不再写死。
- 依赖：`fast-xml-parser` 5.11.1 → 5.12.0（未闭合标签导致 CPU 平方级增长，订阅全是外来 XML）；三条 npm 审计告警清到 0（undici 8.12.4 / zod 4.6.7 / fast-uri 3.1.9）。
- 响应头：HTML 与错误页补 `nosniff` / `Referrer-Policy` / `X-Frame-Options` 与最小 CSP；CSP 的 `font-src 'self' data:` 同时写进 Report-Only 与强制下发的两份片段，片段进仓库，`deploy.sh` 变了才装、装完先 `nginx -t`、不过就还原旧版且不 reload。
- 限速桶：回环请求不进读者限速桶，避免验收被自己的 429 挡住；admission 片段收进仓库。

**为什么**

- 11-20 的提交说得很直白：仓库是公开的，脚本与文档里写死的生产主机、SSH 目标等于把攻击面写在门牌上。

- 订阅源全是外来 XML，解析器的 CPU 放大洞在自家采集链上比告警等级更值钱。

**影响**

- 对运维：安装脚本缺少环境变量会**快速失败**，不会静默连到一台猜出来的机器；CSP 片段有「改仓库即生效」的路径和 `nginx -t` 闸门。
