# 明确额度拒绝的即时冷却

2026-10-29 的生产只读审计发现：同一翻译模型在北京时间 22:20:26—22:20:42 产生 118 条 failed 回执，上游明确返回 HTTP 429、code 14018 与“额度已用尽”。已有持久健康规则会将这个成员冷却一小时，但健康查询缓存六十秒，快速分段循环在缓存刷新前继续使用旧的健康快照。

修复在真实 HTTP 响应边界记录一个轻量、按 service/model 区分的进程内冷却集合。明确额度文字与 HTTP 401/403 即时进入；普通 429、5xx、超时、输出格式失败仍按既有健康、预算和回执规则处理。每次读取健康缓存或等待中的健康查询结果时都叠加最新集合，避免旧查询结果覆盖刚观察到的拒绝。

即时冷却与既有额度规则一样为一小时。到期后由正常工作流尝试，不增加探测请求；较新启动并成功返回的请求可以提前清除即时冷却，较早在途的成功不抹掉更新的拒绝。进程重启后仍由持久回执健康规则接管，不以重启清除供应商额度。

本修改仅影响后续池成员选择，不改变本次请求的计费分类，不把 HTTP 拒绝标成 unbilled，不立即替本次 HTTP 请求购买另一个答复。pending/unknown 和可复用已收到答复仍在完整配置池内按原逻辑恢复。显式单模型配置与全池均不可用时的原有保守回退规则保留，不能声称任意情况下都会换模型。

验证覆盖：缓存健康状态之后实际收到本地上游 429，下一分段立即选择同池健康成员；账本仍保留前一失败回执及其原计费分类。另覆盖冷却到期、较新成功、较早在途成功、普通限速/服务器忙/超时不误判为明确额度墙。
