# 精选与校准

## 一条资料怎么变成精选

1. **收进来**：同一网址、同一内容只留一份。只有标题或订阅摘要的，先抓原文页面再判断。
2. **预筛**（`prefilter.md`）：这是不是本行业的事。宽进，只拦明显无关的：`BLOCK` 的资料不出现在任何公开页面；`PASS` 和拿不准的 `UNKNOWN` 继续往下走。本站的预筛除了拦无关，还**直接把五类噪声拦停**而不只是压分：教育与文旅营销（旅游软文、研学与营地招生、教研培训与课件推销、景区宣传稿）、没有数据的泛泛地方介绍、未经核实的地理传闻、纯机关公文与领导调研（无面向公众的结论）、多主题盘点与汇编；这五类**带着航拍影像、客流数字、地名坐标也照样拦**，因为评分阶段的噪声上限不在代码里（见下面“什么有保证”）。
3. **评分**（`selection-score.md`）：同一份评分标准独立打两次分（0–100）。**两次之和 ≥ 2 × 门槛**就入选，门槛按信源分级不同。页面上显示的分数是两次的平均（向下取整）。
4. **写标题摘要**：入选的和差一点入选的（平均分高于 `understandFloor`），按 `content-understanding.md` 写中文标题、答案先行的摘要、推荐理由和标签；其余的按 `summarize-*.md` 写简短的标题摘要，进“全部动态”。
5. **结构化**（`structure.md`）：分类、标签、主体公司、事实（谁、做了什么、对什么），和评分同时进行。主题页和事件归组靠它。
6. **归组**（`group-*.md`）：不同来源报道的同一件事归成一个事件，事件页有综述（`story-digest.md`），“热门”按事件排。入选的资料要等归组完成（最多 3 分钟）才出现在精选里，避免同一件事先冒出好几条。
7. **日报、周报、月报**（`report-*.md`）：每天 08:00 出日报（前一天 08:00 到当天 08:00 的精选候选），每周一 10:00 出上周周报，每月 1 日 10:30 出上月月报。资料进入站点后若跨过刊期边界才确定精选公开时间，便归入下一期候选池；截止前已确定公开时间、但仍在提交的发布事务，取稿会等它提交后再读取，避免漏过前后两期。最终刊载仍受同一事实去重和版面容量限制。

每一步的提示词都在 `industry/prompts/`，改提示词不用改代码。提示词的版本就是它内容的哈希：改了提示词，之后的新资料按新版判断，已经判过的不会重算。

## 门槛：`industry/selection.ts`

现值只写在 `industry/selection.ts` 里，那个文件头的注释就是它的算式与依据；**下面这段是抄录，改门槛只改代码，不要把数字抄进文档再抄回来。**

```ts
export const SELECTION = {
  thresholds: { T1: 56, T1_5: 59, T2: 62 },  // 两次评分的平均至少要到这个数（入选线之和 112 / 118 / 124）
  understandFloor: 46,                       // 平均分高于它的未入选资料，也按入选的写法写（之和 > 92）
};
```

官方一手信源（T1）门槛低一些，媒体和个人（T2）门槛高一些：同样一件事，官方原文更值得先看。相邻两档差 3 分（两次之和差 6 分），所以 T1_5 与 T2 对同等内容都比 T1 更严。没有门槛的分级（`EXCLUDE_MP`）不参与精选。

**这组数是推出来的，不是校准出来的。** 它由两条硬边界夹出来：《地理研究》当期最好一条的人工两次之和是 119（该源分级 T1_5），要不让期刊层被锁死就得 `2×T1_5 ≤ 118`；而 T1 上实测最高的噪声是 107（例行新闻发布会与工作简报），要关住它就得 `2×T1 > 107`。加上“相邻档余量 ≥ 3”，可行区间只剩 T1 ∈ [54,56]、T1_5 = 59、T2 ∈ {62,63}，取 56 / 59 / 62。**这是 reasoned-but-not-empirically-calibrated：本站没有人工标注的 gold 集（`.data/gold.jsonl` 不存在），所以没有查准率、查全率，也不知道门槛挪 2 分会翻掉几条。** 真正的再校准程序在下一节，需要 `MODEL_CALLS_ENABLED=true`。

## 什么有保证，什么没有

| 保证 | 由谁承担 | 性质 |
|---|---|---|
| 两次之和 ≥ 2 × 门槛才入选；卡片显示平均（向下取整）；`EXCLUDE_MP` 与无门槛分级不评分 | 代码（`editorial/analyze.ts:380`） | 硬保证 |
| 只有 `BLOCK` 停止这条材料；`UNKNOWN` 与 `PASS` 一样往下走；没有中文标题摘要的材料会等待 | 代码（`analyze.ts:343,373`） | 硬保证 |
| 分数必须是 0–100 的整数 | 代码（`ScoreSchema`，`analyze.ts:71`） | 硬保证，**只此一条** |
| 内容类型与五轴权重、12 条噪声上限（营销 `sig≤2`、盘点 `sig≤3`、传闻 `cred≤2`……） | 只有提示词（`selection-score.md:49-87`） | 提示词纪律：五轴从不回传代码，上限没有任何运行时强制 |
| 拦住营销软文、盘点稿、机关公文 | 预筛 `prefilter.md` 的 `BLOCK` | 提示词纪律；真模型下没人验过 |
| 拦住“被错分进 `observation_release`、带着影像与客流的景区推介”（评分 63–70） | 预筛的 `BLOCK` 一条 | **门槛拦不住**：它的两次之和 126–140 高于三档全部入选线；要把它抬到 T1 之外需要 T1 ≥ 71，那会同时把赣江洪水 135、统计局公报 135、区划批复 126 全清空 |
| 例行更新与版本通告（上限 60 分，两次之和 120） | 无 | 120 > 112 且 > 118：**T1 与 T1_5 都关不住它**，只靠预筛与分级摆放；把它关住的唯一门槛写法是把 T1 抬到 61，而那样 119 的期刊层就再次被锁死 |

结论：想给噪声上限加上真保证，得让评分把五轴回传并在 `analyze.ts` 里夹紧（改 `ScoreSchema`，属 `packages/backend`），或在代码里按 `itemType`+噪声标记夹紧分数；单靠 `selection.ts` 的数字做不到，这一点已经被独立审计确认（Wave 2 审计的 W2-M1 条目；审计报告随交付材料在仓库外，仓库内的完整推演记录写在 `industry/selection.ts:8-24` 的文件头注释里）。

## 校准

### 1. 准备样本集

从你自己的信源里挑 100–200 条资料，一条一条标“该选 / 不该选”，存成 `.data/gold.jsonl`（`.data/` 不进 Git）。每行一条：

```json
{"caseId":"law-001","material":{"title":"原文标题","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"信源名称","bodyZh":null,"bodyOriginal":"正文……"},"sourceFacts":{"sourceKind":"rss","sourceTier":"T1","firstParty":true,"language":"zh"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"regulation"},"gold":{"decision":"select"}}
```

| 字段 | 说明 |
|---|---|
| `caseId` | 唯一编号 |
| `material` | 标题、原标题、发布时间、信源名、正文（中文正文放 `bodyZh`，原文放 `bodyOriginal`，有一个就行） |
| `sourceFacts` | 信源类型、分级、是否一手、语言。分级决定用哪个门槛 |
| `samplingContext` | 可选。`benchmarkSplit` 分开发集和留出集，`samplingStratum` 是你自己的分组（比如“新规”“判决”“营销”），看错在哪一类 |
| `gold.decision` | `select` 该选，`reject` 不该选，`either` 两可（不计入准确率） |

`industry/gold.example.jsonl` 有 12 行示范行，但**它们不是标注样本**：按文件头自述，标题与正文都是按真实信源形状编造的示意材料，不能拿来当 gold 集算准确率。用法是复制成 `.data/gold.jsonl`，再逐条换成你自己信源里的真材料和你自己的判断。

几条建议：

- 多放**难例**：差一点就该选、差一点就不该选的。一眼就能判断的放太多，准确率会虚高。
- 分出一部分做**留出集**（`benchmarkSplit: "holdout"`），调提示词只看开发集，最后再用留出集检查一遍，免得把提示词调成只会做这几道题。
- 标注的人最好就是以后读这个站的人，或者和他们口味一致的人。

### 2. 跑评测

这一步要真调模型（预筛一次、评分两次），而 `.env` 里的安全阀 `MODEL_CALLS_ENABLED` 默认是 `false`，直接跑会被 `providers/llm.ts:157` 拒掉。本机按 `docs/manual.md` 第 3.5 节的做法叠一个一次性 env 文件（**不要**改 `.env`）：

```bash
node --env-file=.env --env-file=.env.pipeline scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "第一版评分标准"
```

`--gold` 的默认值也是 `.data/gold.jsonl`（`scripts/eval-selection.ts:19`）——脚本读的是 gold 文件本身，**不会**读 `industry/gold.example.jsonl`，那 12 行只是格式示范。

对每条样本跑一遍预筛和两次评分，输出：

- 准确率、查准率（选出来的有多少是对的）、查全率（该选的有多少选上了）；
- 门槛从 40 到 90 每隔 2 分，各自会得到什么结果（这一列按“均值 ≥ t”算，和线上的“两次之和 ≥ 2×分级门槛”是同一件事的两种写法，看错例时记得换回分级线）；
- 判错的条目，完整报告写到 `.data/eval/`，同时导入后台 SelectBench。

脚本会写库（SelectBench 那一步），主库正被别的作业占用时加 `--no-import`，或把 `DATABASE_URL` 指到 `*_test` 库；样本没写 `sourceFacts.sourceTier` 时按 T2 评（`eval-selection.ts:68`），标注时要填真实分级，否则门槛对错了档。

常用参数：`--models default,deepseek-flash` 同批比较几个模型，`--n 200` 最多抽多少条，`--split holdout` 只跑留出集。同样的输入和提示词再跑不会重复调用模型（有回执复用），只有改过的部分才会产生新调用。**改了 `prefilter.md` 或 `selection-score.md` 之后，提示词版本哈希变了，旧回执不再复用，等于整批重算**——先把开发集缩小到几十条再试改。

### 3. 看错例，改标准，再跑

在后台 SelectBench 里逐条看判错的资料和模型给的理由：

- 该选没选上，多半是评分标准里没说清它为什么重要：在 `selection-score.md` 里把这类价值写进“必须正常评价”的部分，给出例子。
- 不该选却选上了，多半是噪声没压住：写进“必须压住”的部分。但如果错的是营销软文、盘点稿、机关公文这一类（评分上限只活在提示词里、没有代码强制），要写的是 `prefilter.md` 的 BLOCK 清单，让它根本进不到评分那一步；只加一条 `sig≤2` 拦不住它。
- 整体偏松或偏紧，而判错的条目分数都贴着门槛，再调 `industry/selection.ts` 的门槛。

先改标准，再动门槛：门槛只能整体移动，解决不了“哪一类判错了”。每改一次跑一遍，SelectBench 里能看到每一版的对比。

## 换模型

后台“模型与评测”页能看到每一步当前用哪个模型、近期的成功率、耗时和 token 用量，也能直接切换（只影响之后的新任务）。换评分模型之前，先用 `--models` 在同一批样本上比一比。
