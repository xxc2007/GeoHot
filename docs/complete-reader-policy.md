# 完整读者内容发布规则

2026-10-28 根据站长要求执行。读者入口只提供已完成适用工作流的完整文章；后台处理状态不等于发布许可。

## 放行条件

1. 采集材料与分析属于当前文章 revision，筛选结果为 pass，标题和摘要已生成。
2. 来源明确允许站内全文，publication 为 public 且正文模式为 full。仅摘要许可、summary-only 人工状态、缺正文或提取未确认的材料只留在后台，不以导读代替完整文章上线。不得为满足展示要求擅自改写来源许可。
   - 2026-11-01 增补（条目页分级）：完整正文页仍是唯一"文章页"。但 public + editorial + 已过释放门且有中文标题与非空摘要的条目，在正文不可服务时返回**受限页**（`summary-licence`：来源仅准摘要；`pending-workflow`：全文许可但核验未完成）——只呈现标题、AI 导读、来源与原文入口，无正文、noindex、无导出。这是期刊引用的落点，不是以导读代替文章：完整正文一个字不出站，摘要许可状态在页面上如实说明。管理员 summary-only 人工下架仍整条 404；未生成中文稿或摘要为空的行没有受限页（空壳不如 404）。
3. 外文正文须有相同 revision 的完整中文译文，HTML 和文本均非空，且不含替换字符、未还原占位符等明确损坏。中文原文不强制机器翻译；原有短帖及数据保护规则仍适用于相应内容类型。
4. 正文及译文所需图片、视频封面准备完成，并与当前原文、译文、revision 和媒体指纹相符。来源头像、favicon、OG 不阻塞正文发布。
5. 精选条目继续遵守既有释放时间、相关性和入选规则。事件综述、日报等可选派生任务不要求每篇文章都生成一份，但这些出口不得引用尚未就绪的内部条目。
6. 页面与 Markdown 必须完整保留已确认正文的结尾、章节、图表、附件链接、脚注和参考文献。性能优化使用按语言投影、缓存和索引，不允许以固定字符上限裁剪文章。

## 统一执行与失效

网站列表、日期入口、详情、原文切换、Markdown、RSS、公开 API、MCP、分享卡、收藏可用性与聚合引用遵守同一 publication 读取门禁。读者请求不得触发采集、翻译、模型调用或修复。人工重发也必须重新核验当前公开状态，不得重放已隐藏的旧摘要卡片。

`article_workflow_readiness` 是事务失效的后台校验事实，不是人工批准标志。规则版本由代码 `READER_POLICY_VERSION` 定义；旧版本 ready=true 不构成新规则下的放行。原文、分析、译文、publication、必要媒体或来源政策变化使旧事实失效。禁止直接手动将 complete/ready 写为 true 来清理积压。

新规则上线后，先复核近期与精选文章，再按持久游标复核其余获准全文条目。既有 `ops.recover` 每轮只读有限头部并逐篇复核，受语句超时、锁等待、时间预算及资源门禁约束；不批量载入全文，不创建第二套数据库或队列，不依赖个人电脑在线。

## 小内存运行约束

保持现有 Azure 学生服务器规格和既有 R115 读者保护。实时采集、分析、翻译及必要媒体优先，历史回填在资源不足时让行；不提高付费并发、不清除 unknown 回执、不跳过翻译或媒体阶段来制造吞吐。未完成文章继续正常重试，永久性来源限制保留原因供后台核查。

完整性按已取得且可合法展示的材料验证。提取失败、只有 RSS 摘要、源站阻断、正文存在截断信号或必要媒体失败时，不能宣称全文完整。来源许可未确认的文章不会因为后台抓到了正文而自动获得全文展示许可。

回收说明：本轮以服务器实际文件为基线回收既有调度与翻译衔接，保留现有分钟扫描、短轮翻译、资源准入、sources.reserves、分组恢复及空翻译 tick 合并。共享目录有较旧副本，不能用它覆盖已上线调度。

单篇超时或锁等待通过 savepoint 隔离，本轮跳过并推进游标，下次回绕重试，不能让一个异常长文阻塞其后所有历史文章。历史 complete=true 但质量损坏的译文记录 quality_error；既有翻译选择器在六小时冷却后重新准入，仍使用原回执与预算，不删除历史尝试或伪造完成。

规则版本 3 同时检查明确的源正文缺损信号：仅参考文献的 Copernicus/10.5194 论文、明确截断的 Mongabay feed 提示均不得公开，也不得进入全文翻译。Copernicus 按出版方结构提取摘要及全部编号章节，保留公式、图及图注、参考文献与 PDF 附件；长度本身不作为完整证明。缺损事实由既有 ops.recover 每轮最多 5 篇送回普通提取队列，沿用去重、优先级、失败退避和资源保护。新版本使用独立持久复核游标，从近期内容开始，不清除旧队列或回执。

周报、月报引用的历史文章使用独立有界复核游标优先恢复（每轮最多75篇、1.5秒），与普通文章复核共享原有资源保护。日、周、月刊保持既有北京时间出刊计划与 missed-once/小时 catch-up；数据已存在但引用未通过新规则时保持隐藏，不重复购买模型、不把未完成引用改成可见以凑期数。

报刊组稿候选必须与文章公开读取共用 workflowReadyCondition，已精选和有中文摘要不能替代完整工作流。引用无法公开时区分实际撤回、来源全文限制、工作流待核验和其他不可公开状态，不得统一声称“按来源方要求下架”。来源没有撤回时保留可用的出处链接。

历史日报、周报、月报由 reports.repair 每15分钟最多重新处理一期，月报、周报、日报依次按新到旧扫描；使用原期次的时间窗口及现有合格信源素材，不能拿今天的新闻填过去的版面。调用普通组稿器、正常回执和预算，旧版进入 report_revisions，不手改报道结论或 complete/ready 标记。资源不足则延期；全局租约防止重复修复，游标和输入指纹持久保存，输入未变化不重复购买。没有完整候选时保留旧版并等待材料，已重组的期次仍会在后续材料变化时复查。备用信源按既有核验与采集规则接入，不批量解除全文许可或绕过筛选。
