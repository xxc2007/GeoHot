# 后台加载故障隔离

2026-10-25 的 `/admin/runs` 故障调查发现：线上运行页有错误边界，后台父布局没有；父布局在每次导航时重新读取身份和导航计数。身份读取或响应中断会越过子页面错误边界，落到根页面通用错误屏。普通重载能够恢复，并不等于加载路径已经可靠。

本次调整：

- 后台父布局有自己的错误边界。核验失败时保留导航和恢复操作，不渲染受保护子页，不构造管理员身份。
- 普通后台导航复用已加载的布局身份；动作提交和显式重新连接仍重新读取。每个 `/api/admin/*` 请求继续服务端身份核验，写操作继续 CSRF 校验；401 仍跳转登录。
- 运行概览复用私有统计快照设施：后台聚合不阻塞 HTTP，慢查询失败保留最近成功数据，明确标记时间与快照状态；首次尚无数据时显示生成状态，不显示虚假的零积压。
- 自动刷新失败返回可恢复状态，保留本页最近成功结果；不会因为一次统计失败使整个后台退出。
- 管理员请求对响应正文读取同样处理超时和中断，日志只记录请求路径、阶段、状态或错误类型，不记录 Cookie、令牌或正文。
- 后台相对时间在 hydration 后显示，SSR 和浏览器首帧使用同一绝对时间，避免秒数变化导致 React 文本不一致。

故障验证使用真实生产构建和本地响应替身，覆盖身份 503、正文截断、统计 503、会话失效及切页/显式重试行为；不在生产服务器制造数据库故障，不伪造管理员会话。快照的冷启动、持久化、旧值保留与单聚合门禁复用现有测试。

这项修复隔离了已确认的失败路径；服务器或上游整体不可用时仍需要恢复基础服务，不能将错误隔离称为永久零故障。
