# 后台服务器与 Magpie

系统菜单依次是服务器、运行、magpie、用量总览、模型、审计记录、设置。服务器页每 20 秒读取一次轻量系统采样，显示采样时间；采样超过 90 秒明确标记旧数据。采样器不读数据库、密钥、完整环境变量或完整进程参数。

Magpie 以现有管理员会话保护的反代嵌入。固定上游为服务器回环 3430，管理密钥由 API 从 `/etc/geohot/magpie-web-key` 读取，不能放在仓库或 iframe URL 中。代理所有写请求同样检查会话 CSRF 和 Origin。模型推理的 `/v1` 与独立登录路径不经此反代。Magpie 的资源及 fetch URL 适配部署前缀，服务器的 3426/3430 不开放公网监听。

部署采样器前创建 `/run/geohot-server`，root:geohot 0750；或添加 tmpfiles 规则在重启后重建。安装对应 service/timer。API 用户只需读取 0640 的采样文件及管理密钥，不需 sudo。

Magpie 官方更新由每日 timer 执行，保留更新前二进制，在服务重启后核验网关；健康检查失败恢复旧二进制。固定管理密钥在更新时保持。生产服务停止窗口需容纳正在处理的模型请求，不提高模型预算或并发。只启用一种自动更新编排，避免 GUI 内部自动下载与 systemd 重复更新。

访问稳定性调整：

- 运行在小内存主机上的 Node 接口显式设置 V8 堆上限，让垃圾回收先于 cgroup 内存上限触发，避免进程长期陷入换页。
- 可选历史归档遵守 R115 冷却和内存/I/O 压力条件，跳过一轮保留游标，不能清除门禁状态或强行恢复实时协调器。
- 月日历按完整筛选条件合并并发请求，成功缓存 30 秒、失败缓退 2 秒，最多 128 个键；显式测试时间绕过成功缓存，不把失败伪造为空日历。
- 全部动态的列表和可选日历立刻交给 Promise.all 统一观察，避免在列表失败后继续等待日历才挂接拒绝处理。
- nginx 的公开读取白名单不因无关 cookie 而跳过缓存。后台、反馈、写请求、Authorization、Set-Cookie、源站 no-store 和绝对发布时间约束继续排除，不能缓存管理员页面或延长已过期的编辑内容。

验证使用隔离请求和测试数据。正式部署核对源文件哈希，保留旧 build 与不可变资源；实测结果和未覆盖的地区/运营商另写验收材料，不能将桌面模拟说成真实手机网络验收。
